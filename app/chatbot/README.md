# SSOK 챗봇 구성안 — Qwen3-8B

이 문서는 구현 계획이다. 현재 폴더에는 실행 가능한 챗봇 코드가 없으며 기존 추천 API와 DB는 변경하지 않는다.
모델은 Qwen3-8B, Ollama 모델 태그는 `qwen3:8b`를 기준으로 한다.

## 목적과 범위

상품 찾기, 상품 상세·비교, 개인화 추천을 대화로 제공한다. 모든 질문을 상품 벡터 검색으로 처리하지 않고 질문에 맞는 조회 함수를 선택한다. 주문·결제 변경 및 환불 처리는 첫 버전에 포함하지 않는다. 정책 상담은 실제 정책 자료와 별도 조회 경로를 준비한 후 추가한다.

## 구성 요소

| 구성 | 역할 |
| --- | --- |
| Qwen3-8B | 질문과 대화 문맥 해석, 도구 호출 요청, 조회 결과를 근거로 답변 작성 |
| Ollama | Qwen3-8B를 로컬에서 실행하는 모델 서버 |
| FastAPI | 채팅 요청 접수, 세션과 인증 정보 전달, 응답 반환 |
| Python 도구 함수 | 인수 검증, 매개변수화된 SQL 조회, 추천 함수 호출 |
| PostgreSQL + pgvector | 상품·회원 관심 이력·상품 벡터 저장 |
| 기존 E5 모델 | 상품 벡터 생성. 챗봇 답변 생성에는 사용하지 않음 |

챗봇용 LLM은 한 개다. 같은 Qwen 모델을 함수 선택 단계와 결과 설명 단계에서 재사용한다. 기존 E5는 별도의 임베딩 모델이며, 질문마다 상품 벡터를 다시 만들 필요는 없다.

## 요청 흐름

```text
프론트 채팅창
  → 인증된 백엔드 / 채팅 API
  → Qwen: 질문 + 제한된 대화 문맥 + 허용된 도구 정의
  → Python: 도구 이름·인수·접근 권한 검증
  → DB 조회 또는 기존 추천 함수 실행
  → Qwen: 도구 결과를 근거로 답변 작성
  → 서버: 상품 ID 검증 및 실제 상품 카드 구성
  → 프론트: 답변 + 상품 카드
```

첫 버전은 읽기 전용 도구만 제공한다. LLM이 SQL이나 Python 코드를 생성해 직접 실행하게 하지 않는다. 도구 실행 횟수·응답 시간·대화 길이에 상한을 둔다. 지원하지 않는 요청이나 조건이 불명확한 요청에는 안내 또는 추가 질문을 반환한다.

## 제공할 도구

| 도구 | 입력 예시 | 처리 |
| --- | --- | --- |
| `search_products` | keyword, category, max_price, sort, limit | 판매 가능·재고 보유 상품 중 조건을 만족하는 상품 조회 |
| `get_product` | product_id | 상품명·가격·설명·재고 등 실제 등록 정보 조회 |
| `recommend_products` | limit, 선택적 상품 조건 | 인증된 회원의 관심 이력을 이용한 개인화 추천 |

상품 비교는 `get_product`를 비교 대상별로 호출한 뒤 공통 속성으로 설명한다. 회원 ID는 LLM 도구 인수로 받지 않고 서버가 검증한 로그인 문맥에서 전달한다. 로컬 목업 회원 선택 기능은 개발 전용으로 분리한다.

`search_products`는 가격·카테고리 같은 명시적 조건을 먼저 적용한다. DB에 별도 속성이 없는 '무선' 같은 표현은 설명·상품명에서 근거를 찾되, 등록 정보로 확인할 수 없는 성능을 단정하지 않는다. 정렬 방식과 카테고리는 허용 목록으로 검증한다.

## 기존 추천과 연결

`app/recommendation/service.py`의 `recommend_for_member()`를 재사용할 수 있다. 현재 함수는 회원 ID와 개수를 받아 개인화 결과가 있을 때 유사도순, 없을 때 인기순으로 반환한다.

현재 함수에는 가격·카테고리 조건이 없으므로 챗봇의 조건부 추천에 그대로 사용하지 않는다. 조건을 후보 조회 단계에 적용하는 기능을 추가해야 한다. 상위 몇 개를 받은 뒤 필터링하면 실제로 조건에 맞는 후보가 있는데도 없다고 판단할 수 있다.

- 명시적 가격·카테고리 조건은 개인화와 인기순 양쪽에서 유지한다.
- 조건에 맞는 상품 자체가 없으면 관련 없는 인기 상품을 대신 제시하지 않는다. 조건 변경 여부를 묻는다.
- 개인화 후보가 하나라도 있으면 부족한 개수를 인기 상품으로 채우지 않는다.
- 구매 상품 제외는 주문과 상품을 연결하는 데이터가 필요하다. 현재 구현된 것으로 가정하지 않는다.

## 대화 문맥과 답변 규칙

세션에는 최근 대화, 직전에 제시한 상품 ID와 표시 순서, 사용자가 명시한 검색 조건을 보관한다. '두 번째 상품', '그중 더 저렴한 것'을 이 문맥으로 해석한다. 모호하면 다시 묻고, 새로운 조건은 이전 조건 중 무엇을 대체하는지 확인한다.

가격·재고·상품 특성은 도구 결과에 있는 내용만 답변한다. 상품 설명은 데이터로 취급하며 그 안의 지시문을 실행하지 않는다. 도구 오류와 검색 결과 없음은 구분한다. DB가 실패하면 임의의 상품이나 가격을 만들어 반환하지 않는다. 도구 호출 형식이나 검증에 실패하면 제한된 재시도 후 안내한다.

## API 제안

`POST /chat`를 기존 FastAPI 앱에 라우터로 추가할 계획이다. 기존 `/recommendations`는 유지한다.

요청 예시:

```json
{"session_id": "session-example", "message": "5만 원 이하 키보드 찾아줘"}
```

응답 구조:

```json
{
  "session_id": "session-example",
  "message": "조회 결과를 근거로 작성한 답변",
  "products": [],
  "mode": "search"
}
```

`products`에는 서버가 조회한 실제 상품 ID·상품명·가격·이미지 주소를 넣는다. LLM이 만든 상품 객체를 그대로 사용하지 않는다. `mode`는 search, personalized, popular, clarification 등 서버가 확정한 처리 결과다. 세션은 인증된 사용자에게 귀속시키고 다른 회원의 대화에 접근할 수 없게 한다.

## 구현 예정 파일

```text
app/chatbot/
  README.md       # 현재 구성 문서
  router.py       # 채팅 API
  schemas.py      # 요청·응답·도구 인수 스키마
  service.py      # 대화 흐름과 도구 실행 제한
  llm_client.py   # Ollama 호출과 시간 제한
  tools.py        # 검증된 상품 조회·추천 함수
  prompts.py      # 한국어 응답 및 근거 사용 규칙
  sessions.py     # 사용자별 대화 문맥 관리
```

README 이외의 파일은 아직 생성하지 않았다. 새 기능은 AI 저장소에서 구현하며 Java 저장소의 실제 연동은 별도 작업이다.

## 실행 환경 계획

로컬 개발은 Windows의 Ollama와 Python API, 기존 Docker DB를 연결한다. Ollama 설치 후 모델 준비 명령은 다음과 같다.

```powershell
ollama pull qwen3:8b
```

추가할 환경 변수 예시:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
```

DB는 기존 AI `.env`의 `DATABASE_URL`을 재사용한다. Python API까지 Docker에 넣는 경우 localhost는 컨테이너 자신이므로 Windows Ollama에는 `host.docker.internal`로 접속하도록 조정한다. Ollama를 외부에 직접 공개하지 않는다.

현재 requirements.txt에는 FastAPI가 선언되어 있지 않으므로 구현 시 FastAPI·ASGI 서버·HTTP 클라이언트 의존성을 명시해야 한다. 실제 라이브러리 버전과 모델 실행 옵션은 구현 시 검증해 고정한다. 일반적인 상품 질의에서는 불필요한 추론 시간을 줄이는 설정을 우선 검증한다.

모델 파일 크기만으로 실행 메모리를 판단하지 않는다. Docker DB와 함께 구동한 상태에서 메모리·응답 시간을 측정하고 문맥 길이를 제한한다. Qwen3-8B가 목표 응답 시간에 못 미치면 작은 모델 또는 별도 추론 서버를 비교한다.

## 완료 판단

한국어 질문으로 조건 검색, 상품 비교, 문맥을 이어가는 질문, 개인화와 인기순 전환, 결과 없음, 도구 오류를 검증한다. 조건 위반 상품·존재하지 않는 상품·근거 없는 성능 설명을 반환하지 않아야 한다. 목업을 이용해 기대 상품 ID와 실제 응답을 비교하고 모델별 정확도 및 응답 시간을 기록한다.
